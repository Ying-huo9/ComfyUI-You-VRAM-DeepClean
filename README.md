# ComfyUI-VRAM-DeepClean

显存彻底释放 —— 独立通用节点。零第三方依赖。

## 它做什么

三层释放,**Manager 能放的它都放,Manager 不能放的它也放**:

| 层 | 动作 | 覆盖 |
|---|---|---|
| ① ComfyUI 注册模型 | `unload_all_models()` + `soft_empty_cache()` | Checkpoint / VAE / CLIP / LoRA / GGUF-Unet 等官方体系内一切 —— 等同 ComfyUI-Manager「释放模型和节点缓存」按钮 + Memory_Cleanup 节点的全部能力 |
| ② 进程内 GGUF 深度扫描 | gc 找出内存里**所有** `llama_cpp.Llama` 实例,逐个 `close()` 并断开持有引用 | 自建加载器 / llama-TE / llama-cpp_vllm / **任何插件**加载的进程内 GGUF —— ComfyUI-Manager 完全够不着的部分 |
| ③ 终态清扫 | `gc.collect()` + `torch.cuda.empty_cache()` | 归还 Python/PyTorch 的显存碎片 |

执行后终端打印:`[VRAM深度释放] ... 显存空闲 X → Y (本次释放 Z)`。

## 节点形态与用法

- **OUTPUT_NODE**:拖进工作流**不连任何线**,Queue 时也会执行(和 SaveImage 同类)
- **深度扫描**(默认开):关闭则只清理第①层,等同 Manager 按钮
- **任意数据1~8(透传口 \*)**:任意类型、任意数量,**1:1 原样透传**(输入N → 输出N)。
  前端 JS 自动隐藏未用的槽位——**连一个长一个**,视觉上等同无限扩展;
  JS 不生效时最多显示全部 8 路,功能不受影响。
  - 拉一根线进来:强制本节点排在最后执行
  - 串多根线:兼作执行顺序控制器,把工作流排成一条确定性的链
  - 释放发生在**节点执行的那一刻**:前面用完的模型全腾出去,后面的模型满空间加载

### 放置建议

- **跑完生图想腾显存跑下一个工作流**:放链尾,或从最后一个数据节点拉线进来
- **多段工作流中途释放**(如 采样→释放→VAE):用透传口串在两段之间
- 注意:如果本节点排在还**需要**模型的节点之前,那些节点会重新加载模型(多等几秒,不会出错)

## 诚实的边界

- **CUDA 上下文底噪 ~300-500MB 释放不了**:每个 GPU 进程的固定开销,只有退出 ComfyUI 才归零。除此之外能接近全空。
- 深度释放是"激进但安全":被释放的插件下次执行会自己重新加载模型,行为正确。
- 系统 RAM 的节点输出缓存是 ComfyUI 故意保留的,运行中谁也清不掉。

## 安装

放入 `ComfyUI/custom_nodes/`,重启 ComfyUI。搜索「**显存彻底释放**」或「VRAMDeepRelease」。
